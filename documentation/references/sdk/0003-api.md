# Method reference

This page lists the methods of the `@pstdio/sdk` HTTP client and what the other SDK entry points export.

Import a declared `@pstdio/sdk` subpath. The package has no root entry point.
The [SDK overview](0001-overview.md) lists all entries and their dependency requirements.

For page limits, canonical fields, project scope and 0.44 aliases, see
[client conventions](../extensions/0023-client-conventions.md).

## HTTP client

```ts
import { createClient, PstdioApiError } from "@pstdio/sdk/client";

const client = createClient();
const projects = await client.projects.query();
```

`createClient(options?: ClientOptions)` accepts `baseUrl`, `token`, and `fetch`.
Outside the browser, it reads `PSTDIO_API_URL` and `PSTDIO_API_TOKEN` when those
options are omitted. The fallback URL is `http://127.0.0.1:19840`.

`createRequest(options: ClientOptions)` returns the low-level request function.
HTTP failures throw `PstdioApiError`, which exposes `message` and `status`.
Transport failures throw `PstdioConnectionError`, with the original error in `cause`.
Cancelled requests keep the abort reason. Hosts can report connection loss once
in their status bar while keeping loaded views visible. Sync reconnects after
a closed stream or missed heartbeats and calls `onConnected` when ready again.
See the [request types](../../../packages/sdk/src/client/request.ts) for request
headers, cancellation, and other options.

`client.filesystem.drives()` returns `{ drives }`, with each drive's `name` and root
`path` on the Windows runtime host. Other platforms return an empty array.

`extensions.install` installs a catalog extension or an uploaded folder into a project,
the same path `pst extensions add` uses. `extensions.diagnostics` returns the checks
behind `pst extensions check`. `extensions.streamCommand` runs a command and streams its
chunks and final outcome; it replaces `extensions.stream`. `runtime.environment` returns the runtime's stable environment ID, and
`projects.bindEnvironment` binds a known project ID to a folder in that environment,
as `pst projects environment` and `pst projects bind` do.

See the [client guide](../../guides/sdk/0001-client.md) for sessions, file attachments,
connections, and remote automation examples. [Board views](../cli/0009-board-views.md) describes the `views` group.

## Release availability

The table follows the source on `main`. `@pstdio/sdk` 0.43.1, the current stable
release, has every method above except the ones marked with \* or †. Those include all
of `client.assets`, the bounded `query` methods, `sessions.iterate`, and
`extensions.streamCommand`. On 0.43.1, use the methods marked deprecated here, such
as `projects.list` and `extensions.stream`; they are not deprecated in that release.

The methods marked with an asterisk are in `0.44.0-nightly` builds and ship in the release after 0.43.x. Each one
needs both the newer SDK and a Prompt Studio app from that release. Installing a
newer `@pstdio/sdk` does not add the API routes to an older app. See
[App, SDK, and extension API versions](../extensions/0014-api-versioning.md#app-sdk-and-extension-api-versions).

The methods marked †, `client.sessions.steer`, `client.sessions.retainResources`, `client.projects.folder` and `client.projects.chooseFolder`, are unreleased additions after 0.44.0 and need both the newer SDK and host. See [live input](#live-input) for steering.

`client.projects.folder(projectId)` and `client.projects.chooseFolder(projectId, input)` read and set where a project's files are on this device; see [Get your cloud projects on a new computer](../../guides/sdk/0004-device-login.md#get-your-cloud-projects-on-a-new-computer).

`client.sessions.retainResources(sessionId)` keeps a conversation's native resources while a client has it open, including after its run finishes. It returns a connection with `close()`. Close it when the tab closes; the host then keeps the session ready for 30 minutes after the last client's interest or active work ends. The connection shares the session stream, restores interest after disconnect, and does not load history or start a run. Idle providers release their resources without deleting the conversation.

## Planner commands

Tickets, statuses, and tags belong to the Planner extension. Use its commands
through `client.extensions.execute`, or use the `pst tickets` CLI aliases.
The installed extension must be enabled in the project.

```ts
const response = await client.extensions.execute("pstdio.pstdio-planner.command.list-tickets", {
  projectId,
  params: { status: "In Progress" },
});

if (response.outcome.status === "success") {
  console.log(response.outcome.value);
}
```

Use `client.extensions.listCommands(projectId)` to discover command IDs. IDs include
the publisher, extension name, contribution kind, and local ID. Do not construct
them from the package name alone.

## Extension authoring

`@pstdio/sdk/extensions` exports contribution helpers, typed references, command
and renderer contexts, storage contracts, and the webview client. It also exports
`EXTENSION_API_VERSION`, the extension API version of that SDK build: `0.1.6` in
0.43.1 and `0.2.0` on `main`. `engines.pstdio` declares caret ranges that include
the host's version, such as `^0.1.0`. See [API versioning](../extensions/0014-api-versioning.md).

Use the [composition cookbook](../../guides/extensions/0002-workbench-cookbook.md) for `definePage`,
shared placement items, resource identity, navigation, controls, `qualifyRef`,
and typed `GuestHost.call` capabilities. The
[React entry](../../../packages/sdk/src/extensions/react/index.ts) provides
`useCommandQuery` and `useCommandMutation` for webviews.

## Other entries

Use [`ctx.storage.records`](0004-storage.md) for durable grouped writes, observed
revisions, and conflict resolution. Keep exact operation IDs for storage retries;
do not rerun commands with external effects. `ctx.storage.records` and
`ctx.storage.assets` ship in the release after 0.43.x; see
[storage availability](0004-storage.md#availability).

- `@pstdio/sdk/api` exports HTTP request and response types.
- `@pstdio/sdk/resources` exports [product resource types](0002-resources.md).
- `@pstdio/sdk/prompts` exports `renderPrompt(template, data)` for Mustache rendering.
- `@pstdio/sdk/hooks` is deprecated in 0.44. Use typed hooks from `@pstdio/sdk/extensions`; external clients use `client.sessions.followUp(sessionId, input)`. The old hook contexts, payload mirror and singular session facade remain through 0.44.
- `@pstdio/sdk/data` exports draft layout, frontmatter, and ID/name resolution helpers. See [data exports](../../../packages/sdk/src/data/index.ts).
- `@pstdio/sdk/testing` exports command contexts and in-memory storage, file, and resource adapters for extension tests. See [testing exports](../../../packages/sdk/src/testing/index.ts).

## Live input

`client.sessions.steer(id, { expectedRunStartedAt, prompt, attachments })` sends new input only to the captured active run. Read its identity from `getQueuedFollowUps(id)` before uploading files. Each attachment is `{ fileId }`. Optional `summaryFromSessionId`, `summaryFormat` (`brief` or `detailed`), and `summaryRole` (`assistant` or `all`) can supply a source summary with or without a prompt. Live input keeps the current execution settings.

The result is `accepted`, `rejected`, or `uncertain`, as for queued steering below. Inactive, unsupported, blocked, or changed runs reject without starting or queuing another turn. Uncertain delivery retains held evidence and attachments. Do not retry automatically, including after a failed HTTP request whose delivery outcome is unknown.

## Queued requests

`client.sessions.getQueuedFollowUps(id)` returns each request's queue position, revision, prompt, model, complete parameters, and attachment references. It also reports the current run identity and steering availability.

`updateQueuedFollowUp(id, position, { prompt, expectedRevision, model, params, attachments })` saves a complete request without sending input. Optional fields keep their saved values; null model selects the provider default, null parameters reset defaults, and an empty attachment list removes references. A stale revision fails without modifying another request.

`combineQueuedFollowUps(id, targetPosition, { sourcePosition, sourceRevision, targetRevision })` combines two saved requests with matching settings. Text follows their queue order and attachments are deduplicated.

`steerQueuedFollowUp(id, position, { expectedRevision, expectedRunStartedAt })` sends one saved request into supported active work. Inspect `status`: `accepted` includes a delivery ID; `rejected` includes a reason and message; `uncertain` includes a delivery ID and message. Never automatically retry uncertain delivery. Unsupported harnesses return a typed rejection.
