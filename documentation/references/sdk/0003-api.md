# Method reference

This page lists the methods of the `@pstdio/sdk` HTTP client and what the other SDK entry points export.

Import a declared `@pstdio/sdk` subpath. The package has no root entry point.
The [SDK overview](0001-overview.md) lists all entries and their dependency requirements.

## HTTP client

```ts
import { createClient, PstdioApiError } from "@pstdio/sdk/client";

const client = createClient();
const projects = await client.projects.list();
```

`createClient(options?: ClientOptions)` accepts `baseUrl`, `token`, and `fetch`.
Outside the browser, it reads `PSTDIO_API_URL` and `PSTDIO_API_TOKEN` when those
options are omitted. The fallback URL is `http://127.0.0.1:19840`.

`createRequest(options: ClientOptions)` returns the low-level request function.
HTTP failures throw `PstdioApiError`, which exposes `message` and `status`.
Transport failures throw `PstdioConnectionError`, with the original error in `cause`.
Cancelled requests keep the abort reason. Hosts can report connection loss once
in their status bar while keeping loaded views visible. Sync reconnects after
a closed stream or missed heartbeats and calls `onConnected` when ready again.
See the [request types](../../../packages/sdk/src/client/request.ts) for request
headers, cancellation, and other options.

## Planner commands

Tickets, statuses, and tags belong to the Planner extension. Use its commands
through `client.extensions.execute`, or use the `pst tickets` CLI aliases.
The installed extension must be enabled in the project.

```ts
const response = await client.extensions.execute("pstdio.pstdio-planner.command.list-tickets", {
  projectId,
  params: { status: "In Progress" },
});

if (response.outcome.status === "success") {
  console.log(response.outcome.value);
}
```

Use `client.extensions.listCommands(projectId)` to discover command IDs. IDs include
the publisher, extension name, contribution kind, and local ID. Do not construct
them from the package name alone.

## Extension authoring

`@pstdio/sdk/extensions` exports contribution helpers, typed references, command
and renderer contexts, storage contracts, and the webview client. The current host
extension API version is `EXTENSION_API_VERSION`, such as `0.1.0`. `engines.pstdio` declares caret ranges that include it, such as `^0.1.0`. See [API versioning](../extensions/0014-api-versioning.md).

Use the [composition cookbook](../../guides/extensions/0002-workbench-cookbook.md) for `definePage`,
shared placement items, resource identity, navigation, controls, `qualifyRef`,
and typed `GuestHost.call` capabilities. The
[React entry](../../../packages/sdk/src/extensions/react/index.ts) provides
`useCommandQuery` and `useCommandMutation` for webviews.

## Other entries

- `@pstdio/sdk/api` exports HTTP request and response types.
- `@pstdio/sdk/resources` exports [product resource types](0002-resources.md).
- `@pstdio/sdk/prompts` exports `renderPrompt(template, data)` for Mustache rendering.
- `@pstdio/sdk/hooks` exports hook API contracts.
- `@pstdio/sdk/data` exports draft layout, frontmatter, and ID/name resolution helpers. See [data exports](../../../packages/sdk/src/data/index.ts).
- `@pstdio/sdk/testing` exports command contexts and in-memory storage, file, and resource adapters for extension tests. See [testing exports](../../../packages/sdk/src/testing/index.ts).

## Queued requests

`client.sessions.getQueuedFollowUps(id)` returns each request's queue position, revision, prompt, model, complete parameters, and attachment references. It also reports the current run identity and steering availability.

`updateQueuedFollowUp(id, position, { prompt, expectedRevision, model, params, attachments })` saves a complete request without sending input. Optional fields keep their saved values; null model selects the provider default, null parameters reset defaults, and an empty attachment list removes references. A stale revision fails without modifying another request.

`combineQueuedFollowUps(id, targetPosition, { sourcePosition, sourceRevision, targetRevision })` combines two saved requests with matching settings. Text follows their queue order and attachments are deduplicated.

`steerQueuedFollowUp(id, position, { expectedRevision, expectedRunStartedAt })` sends one saved request into supported active work. Inspect `status`: `accepted` includes a delivery ID; `rejected` includes a reason and message; `uncertain` includes a delivery ID and message. Never automatically retry uncertain delivery. Unsupported harnesses return a typed rejection.
