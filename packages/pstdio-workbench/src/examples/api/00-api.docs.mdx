# Placements and pages

This guide uses the Core API from `@pstdio/workbench`. A View defines content. A placement puts that View in a region
for the lifetime of the shell, a mode, or a page. The workbench renders panel chrome around each placement instance.
Authors do not register panels.

A placement's `item` decides its lifecycle:

- A static item (`kind: "view"`) has one instance and declares a `presence`: `"fixed"` placements always show and
  cannot close, `"open"` placements start open and the user may close them, `"closed"` placements stay hidden until an
  action or the Add panel opens them. A saved user choice wins over `"open"` and `"closed"` on the next visit.
- A resource item (`kind: "resource"`) has one instance per opened resource. It declares a `cardinality` and has no
  initial visibility: nothing shows until an action supplies a resource.

Opening always goes through the shared navigation executor. `workbench.navigation.openPage(...)` navigates to a page,
and `workbench.navigation.openPanel(...)` opens or activates a declared placement.

## Static placement and presence

The View and placement have different ids in this example. The placement declares `presence: "closed"`, so nothing
shows at registration; the module opens it through `navigation.openPanel`. Press the button inside the workbench:
opening the placement again selects its existing `default` instance.

<Source of={ApiStories.StaticPlacement} />

### What each field means

- `views.registerView({ id, title, body })` defines reusable content. Registering a View opens nothing.
- `shellPlacements.registerPlacement({ id, item, region })` declares one shell-owned placement.
- `item.kind: "view"` makes this a static placement with a single instance.
- `item.viewId` names the registered View to render.
- `item.presence: "closed"` keeps the placement hidden until something opens it. `"open"` would show it right away,
  and `"fixed"` would show it permanently with no close button.
- `region: "main"` selects the region that hosts the instance.
- `navigation.openPanel({ panel: { kind: "shell-placement", id } })` opens the placement through the shared executor.
  Opening an already-open static placement activates the existing instance instead of adding a tab.

## Resource placement with `cardinality: "many"`

The placement binds one View to the `document` resource kind with `cardinality: "many"`. Preview Alpha, then Preview
Beta: Beta replaces the unpinned Alpha preview. Pin a document before previewing the other one to keep both tabs.
Cardinality controls only how instances map to resources. It does not control initial visibility (a resource placement
always starts empty) and it does not control closability (resource tabs are always closable).

<Source of={ApiStories.ResourceTabs} />

### What each field means

- `item.kind: "resource"` makes this placement resource-bound: each opened resource becomes one instance.
- `item.resourceKinds` lists the resource kinds this placement accepts.
- `item.cardinality: "many"` keeps one instance per resource URI. Opening the same resource again selects its
  existing tab instead of duplicating it.
- `openPlacement({ placementId, resource, open })` supplies the resource that creates or selects an instance.
- `open: "preview"` creates a replaceable tab; the next preview replaces it. `open: "pin"` keeps the tab while other
  resources open. The open intent applies only to `"many"` placements.
- `title` labels the instance tab; without it the tab uses the resource label.

## Resource placement with `cardinality: "one"`

The inspector declares `cardinality: "one"`. Open main, then release: the placement keeps one instance and rebinds it
to the newest resource. Use `"one"` for inspectors and detail panels that always follow the latest selection.

<Canvas of={ApiStories.ResourceRebind} sourceState="none" />

<Source of={ApiStories.ResourceRebind} />

### What each field means

- `item.cardinality: "one"` keeps a single instance. Opening resource B while A is open rebinds the same instance to
  B; no second tab appears.
- Open intent (`"preview"` and `"pin"`) is not accepted here because there is never more than one tab.
- Everything else matches the `"many"` example: the placement starts empty, and its one instance closes like any
  resource tab. Cardinality never changes initial visibility or closability.

## Tab presentation

A tab may replace its View icon with a dynamic status indicator. The workbench renders the indicator as the one leading
glyph instead of showing the indicator and View icon together.

<Source of={ApiStories.TabPresentation} />

### What each field means

- `tab.query` returns the current tab snapshot: an optional label, icon, indicator, and menu.
- `tab.refreshEvents` lists the events that invalidate the snapshot and re-run the query.
- `indicator` supplies a leading status glyph with an optional color and accessible label.

## Page composition

A page declares every placement it owns as slots. Navigating to another page replaces that placement set in one
operation. Mode-owned placements remain only when the target page uses that mode.

This example begins on the Session page. Its action navigates to Lab. The Lab page replaces the Session content
instead of opening beside it.

<Source of={ApiStories.PageReplacement} />

### What each field means

- `pages.registerPage({ id, ref, path, modeId, slots })` declares a routed page and everything it places.
- the `role: "primary"` slot is the page's routed content in `main`. It is always present while the page is open and
  the user cannot hide the slot itself.
- an auxiliary slot with a `viewId` is a static panel the page owns; its `presence` follows the same three values as
  placements.
- an auxiliary slot with a `binding` opens instances only when an action supplies a resource; `openOn:
  "page-resource"` also opens it for the page's own resource when the kind matches.
- `navigation.openPage({ page, resource? })` selects the page's mode, commits one canonical location, updates URL and
  history once, and reconciles the page placements in one operation.
