# Extension API

Use the Extension API to build tools that Prompt Studio can install, validate, enable, and remove. This is the only
workbench authoring API available to first-party and third-party extensions.

| | Extension API |
| --- | --- |
| Audience | Extension developers and agents that build extensions |
| Package | `@pstdio/sdk/extensions` |
| API version | `1.0.0-alpha.10` |
| Code location | An extension package |
| UI runtime | Native host renderer or isolated webview |
| Host access | Validated contributions and declared capabilities |

## Extension entry point

Each contribution has a local id and a typed ref. `defineExtension` collects those contributions. Package identity
comes from `package.json`.

<Source language="tsx" code={firstExtensionSource} />

`defineExtension` accepts arrays named for each contribution type. In this example:

- `views` contains reusable content definitions.
- `pages` contains page locations and their placements.
- `navigationItems` contains user actions that open those locations.

The SDK adds a typed `ref` to every `define...` result. Pass the ref to another contribution instead of copying string
ids. The host adds the extension id when it loads the package.

## Views

`defineView(...)` defines content and does not place or open it.

| Field | Required | Meaning |
| --- | --- | --- |
| `id` | Yes | Stable id inside this extension. The SDK creates `view.ref` from it. |
| `title` | Yes | Default user-facing label. It may be a string or a localizable value. |
| `icon` | No | Design-system icon name used where the host shows View chrome. |
| `body` | Yes | Native View or webview definition. |
| `body.kind` | Yes | Selects `tree`, `file`, `controls`, `dataTable`, `kanban`, or `webview`. |

The remaining `body` fields belong to the selected kind. For example, a tree `body` callback returns sections and
nodes. A file body supplies `load` and optional `save`. A webview body declares its packaged entry and capabilities.
Extensions cannot supply React or register a renderer directly.

## Pages and slots

`definePage(...)` owns a route and its page panels. `resource: { kinds }` constrains an optional routed resource. Main presentation is separate.

| Field | Meaning |
| --- | --- |
| `main: { kind: "view", view, cardinality }` | Renders routed content. Multiple instances require a resource-bound page. |
| `main: { kind: "panels", empty }` | Renders peer Main panels and shows the empty view when none are open. |
| `slots` | Additional panels with stable local ids and generated refs such as `page.panels.inspector`. |
| `parent` | Parent page for breadcrumbs and closing the last routed resource view. |

Page slots and mode placements share `item`. Static items use `kind: "view"`, `view`, and `presence`. Resource items use `kind: "binding"` and `binding: { kinds, view, cardinality, add? }`.

`presence` is `fixed`, `open`, or `closed`. Saved user choices win over the initial open or closed state. Fixed panels cannot close. `cardinality: "one"` rebinds one instance; `"many"` retains separate resource instances. A binding opens when given a resource, or on matching page navigation with `openOn: "page-resource"`.

Use `ResourceRef` with `type`, `id`, and optional `label`. URI conversion belongs to routing and persistence adapters. Panel navigation preserves the page resource, URL, and breadcrumbs. Compound targets prepare page and panel steps before committing; commands and links remain standalone actions.

## Mode placements

`definePlacement(...)` attaches a view or resource binding to a mode independently of its pages. It declares `id`, `mode`, `item`, and `region`. Region choices are Main, Side, and Secondary. Page changes within a mode retain shared placement identity. `mountStrategy: "keep-mounted"` preserves local state until the owner leaves.

Modes own `regionSettings` for size, collapsibility, and tab policy. A lone closable panel shows its tab by default. `alwaysShowTabs` explicitly overrides that single-tab policy.

Omitted `chrome` entries retain the host content. Every custom mode gets default host navigation. A view ref replaces that chrome entry; `false` hides it.

Export `qualifyRef(owner, ref)` from a provider contract module for cross-extension use. Local contribution definitions stay local. The helper preserves command types and qualifies nested page-panel refs.

Webviews declare `placement.close` to close themselves with `host.call("placement.close", {})`. The host supplies the calling placement identity and uses the native tab close controller.

## Keybindings

`defineKeybinding(...)` binds a keyboard chord to a navigation action.

| Field | Required | Meaning |
| --- | --- | --- |
| `id` | Yes | Stable id inside the extension. |
| `key` | Yes | Default chord, such as `mod+shift+h`. `mod` is Cmd on macOS and Ctrl elsewhere. |
| `mac`, `linux`, `win` | No | Platform overrides for `key`. |
| `action` | Yes | Any navigation target. A page or panel binds directly; no wrapper command is needed. |
| `when` | No | Context expression that gates the chord. |

## Navigation items

`defineNavigationItem(...)` gives the user a visible way to run an action.

| Field | Required | Meaning |
| --- | --- | --- |
| `id` | Yes | Stable item id inside the extension. |
| `owner` | Yes | Mode or page whose navigation tree receives the item. |
| `slot` | `content` | Pinned `header`, scrolling `content`, or pinned `footer`. |
| `group` | No | Visible section label. Items with the same group are rendered together. |
| `label` | Yes | User-facing item label. |
| `icon` | No | Design-system icon name. |
| `when` | No | Context expression that controls visibility. |
| `action` | Yes | Page, panel, command, link, or compound navigation target. |

## UI contributions

| Helper | What it defines |
| --- | --- |
| `defineView` | A webview or a native tree, file, controls, Kanban, or data table view |
| `definePage` | A route, optional resource, Main presentation, and additional panels |
| `defineMode` | A long-lived context with supported workbench regions and region settings |
| `definePlacement` | A mode-owned view or resource binding |
| `defineNavigationItem` | A page, panel, command, link, or compound navigation action |
| `defineKeybinding` | A keyboard chord bound to any navigation target |
| `defineNavigationTree` | A tree view added to a mode or page navigation slot |
| `defineViewMenu` | A view placed in the menu area of another view |
| `defineResourceKind` | Domain identity, resource bindings, and typed menu slots |
| `defineStatusBarItem` | A view placed in the leading or trailing status bar slot |
| `defineSettingsSection` and `defineSettingsPanel` | Extension settings in shared host settings |
| `defineStatuses` | Workflow states used by native collection views |

## Native view bodies

| `body.kind` | Extension supplies | Prompt Studio supplies |
| --- | --- | --- |
| `tree` | Sections, nodes, children, and actions | Tree interaction, scrolling, expansion, and customization |
| `file` | Load and optional save callbacks | Text, code, Markdown, and image rendering |
| `controls` | Parameter declarations, values, and mutations | Shared form controls and validation |
| `dataTable` | Columns, rows, and actions | Sorting, paging, selection, and table layout |
| `kanban` | Attributes, rows, statuses, and mutations | Board grouping, filtering, dragging, and card layout |
| `webview` | A packaged UI entry and requested capabilities | Isolation, bridge transport, theme, and capability checks |

Renderer callbacks receive an extension context and structured input. They do not receive the workbench core or a React
render function.

Use the Onboarding guide to build a first page. The Renderers guide covers every `body.kind` with a live preview,
