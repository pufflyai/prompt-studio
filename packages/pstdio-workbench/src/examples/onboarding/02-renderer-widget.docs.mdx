# 2. Add A Renderer And Widget

A widget is a declarative slot: `{ id, area, rendererId, config?, areaSize? }`.
It carries no UI code. A renderer is the React (or bridge) implementation looked
up by `rendererId`. Registration alone doesn't make the widget visible —
`layout.openWidget(id)` creates the placement that mounts it.

Why the split:

- One renderer can back many widgets — different `config` per placement, same
  React component.
- A widget's `rendererId` can change without rewriting layout state — useful for
  swapping implementations (e.g. React → bridge, or feature-flagged variants).
- Widgets persist in layout state; renderers don't. Layout serialisation only
  needs to remember which widget id sits where, not what code rendered it.

Required registrations:

- `renderers.registerRenderer({ id, render })`.
- `layout.registerWidget({ id, area, rendererId })` — declares the slot.
- `layout.openWidget(id)` — creates the placement (an opened instance).
