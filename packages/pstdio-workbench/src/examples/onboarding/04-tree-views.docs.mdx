# 4. Add Tree Views

A tree renderer is a renderer kind specialised for sectioned hierarchies. The
contribution provides three accessors:

- `getBody(ctx)` — required, returns `TreeViewSection[]` (sections with
  optional labels and a flat node list each). Rendered as the scrollable body.
- `getFooter(ctx)` — optional, returns `TreeNode[]`. Rendered as a compact
  sticky footer (no section headers). Used for entries like "Help" / "Settings".
- `getChildren(node, ctx)` — lazy children for any node, called on expand.

<Canvas of={OnboardingStories.TreeViews} sourceState="shown" />

`renderers.registerTreeRenderer({ id, ... })` auto-registers a widget renderer
with the same id. Place it like any other content:

```ts
ctx.renderers.registerTreeRenderer({ id: "docs.tree", title: "Docs", getBody, getChildren });
ctx.layout.registerWidget({ id: "docs.tree", area: "left", rendererId: "docs.tree" });
ctx.layout.openWidget("docs.tree");
```

Nodes carry display data only at this stage — no resources, no actions. The
next story attaches resources so clicking a node opens a tab.

Tree expansion and selection state lives in the renderer registry's tree store
(`workbench.renderers.treeStore`), keyed by tree id. It persists across mounts
when a `treePersistence` adapter is supplied to `createWorkbenchCore`.
