# 14. Resources, Locations, and Panels

These terms describe different things:

- A **Resource** is domain identity: ticket `PS-199`, workspace `alpha`, or a settings page.
- A **Panel** is a UI instance that presents content in `main`, `secondary`, `side`, or another region.
- A **Location** is navigation state: the active Resource plus the Main Panel returned by its presenter.

A Panel definition is never declared as a Location. The navigation operation establishes that relationship:

```ts
ctx.resources.registerPresenter({
  id: "tickets.presenter",
  canOpen: (resource) => resource.kind === "ticket",
  open: (resource) => ctx.layout.openPanel("tickets.editor", { resource }),
});

await ctx.resources.openResource(ticket);
```

After the presenter returns, `openResource` makes that Panel instance the Location and records navigation. Opening the
same definition with `layout.openPanel` directly displays a Panel without changing Location, history, or breadcrumbs.
A mode likewise establishes the first Main Panel it seeds as that mode's Location before it opens supporting Panels.

## Supporting Panels

`eligibleLocations` explicitly marks a Panel as subordinate and controls where it can appear:

```ts
ctx.layout.registerPanel({
  id: "tickets.editor",
  title: "Ticket",
  region: "main",
  rendererId: "tickets.editor.renderer",
  resourceKinds: ["ticket"],
  panelMenus: [
    {
      id: "tickets.properties",
      title: "Properties",
      side: "right",
      rendererId: "tickets.properties.renderer",
    },
  ],
});

ctx.layout.registerPanel({
  id: "tickets.terminal",
  title: "Terminal",
  region: "secondary",
  rendererId: "terminal.renderer",
  eligibleLocations: { resourceKinds: ["ticket"] },
});
```

`resourceKinds` is renderer input: it says which Resources the Panel can present. It does not make the Panel a
Location. `eligibleLocations` says the Panel is supporting content and limits the Locations that may own it. `region`
does not carry navigation meaning. Closability belongs to the open placement, not the registered Panel.

Panel Menus are nested under their owning Panel through `panelMenus`. They follow the selected instance and never
become tabs or Add-panel entries.

## History and persistence

Each successful Resource navigation records its Location and the selected supporting Panel in every Panel region.
Back and Forward restore that snapshot without adding another entry. Each Location owns its supporting Panel
placements and selection, so returning to it restores the same tabs, menus, sizes, and open state.

## Extension composition

Extensions declare panel bodies and composition placement separately:

```ts
panels: {
  ticket: {
    title: "Ticket",
    show: { for: "ticket", region: "main", required: true },
    webview: { entry: packageAsset("./ticket.tsx", import.meta.url) },
    panelMenus: {
      properties: {
        title: "Properties",
        side: "right",
        renderer: { kind: "controls", id: "ticketProperties" },
      },
    },
  },
  report: {
    title: "Report",
    show: {
      for: "ticket",
      region: "secondary",
      allowedRegions: ["secondary", "side"],
    },
    webview: { entry: packageAsset("./report.tsx", import.meta.url) },
  },
}
```

`required` makes the resolved placement non-closable. Optional placements can be closed and restored through Add
Panel. A mode may move a panel only within its declared `allowedRegions`.
