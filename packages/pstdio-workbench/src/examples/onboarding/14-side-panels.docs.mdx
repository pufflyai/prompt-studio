# 12. Choose the correct workbench region

The area map shows every supported placement region at once. Use it to choose an API target, not as a product layout.
Most extensions need only `main`, `sidenav`, `secondary`, or `side`.

The Activity Bar is the narrow strip at the far left. Panel menus are attached to the left and right edges of Main,
Secondary, and Side. They collapse into **Open … menu** buttons when a panel is narrow. Drag a visible menu's resize
handle to change its width or collapse it.

`workbenchRegions` is the canonical region list. `main`, `secondary`, and `side` are panel regions. Each panel owns a
left and a right menu region through `viewMenus.registerViewMenu`. The example attaches both menus to all three panel
Views so you can inspect all six menu regions. The status bar is different: it is not a placement region, so the example
registers a backing View through `workbench.statusBar` instead. The complete area map also lives under **Reference →
Core API → Region map**.

## Side Panel presentation

The Side Panel supports attached, floating, and closed presentations. Hosts can disable detachment when floating
content does not suit the application, such as Kiln's inspector:

```tsx
const workbench = createWorkbench({
  initialSidePanelMode: "attached",
  sidePanelDetachable: false,
});
```

`sidePanelDetachable` defaults to `true`. Setting it to `false` removes the Float Side Panel button and the bubble
launcher. The navigation bar still closes and reopens the attached panel. Saved floating state and calls to
`workbench.sidePanel.setMode("floating")` resolve to `"attached"`.

Pass `sidePanelBubbleIcon` to the React host to choose a bubble icon. This accepts a React node and defaults to the
chat icon. It changes the icon while keeping the launcher's tooltip, accessible label, and click behavior:

```tsx
import { SlidersHorizontal } from "lucide-react";
import { Workbench } from "@pstdio/workbench/react";

<Workbench workbench={workbench} sidePanelBubbleIcon={<SlidersHorizontal size={20} />} />;
```

The bubble is shown only for closed panels that allow detachment. See the Side Panel stories in the Core API reference
for the default icon, a custom icon, and a panel that stays attached.

## What each field means

`createRegionMapModule()` returns one module contribution. `id` is the module's stable identity, and `activate(ctx)`
registers everything through the module context. `RegionMapPlaceholder`, `regionLabels`, `describeSurface`,
`createRegionResource`, `regionResourceKind`, and `regionWidgetId` are local example helpers, not workbench API.

The setup calls:

- `ctx.sidePanel.setMode("attached")` docks the Side region so it is visible. The other modes are `"floating"` and
  `"closed"`.
- `ctx.resources.registerKind({ kind, label, icon })` declares the resource kind the example's region resources use.

The Views and the status bar:

- `ctx.views.registerView({ id, title, body })` defines one View per region. `body.kind: "react"` renders the
  placeholder content.
- `ctx.statusBar.registerItem({ id, viewId, slot })` places a backing View in the status bar. `slot` is `"leading"` or
  `"trailing"`. The status bar has its own registry because it is not a placement region.

The overlay:

- `ctx.overlays.registerOverlay({ id, viewId, config })` declares an overlay backed by a View.
- `config.modal: false` keeps the rest of the workbench interactive while the overlay is open.
- `config.closeOnInteractOutside: false` keeps the overlay open when the user clicks elsewhere.
- `workbench.overlays.openOverlay(id)` opens it. The button in the Main region calls this.

The shell placements:

- `ctx.shellPlacements.registerPlacement({ id, item, region })` places one View in one region. The shell owns these
  placements, so they exist in every mode.
- `item.kind: "view"` says this is one static View rather than a resource-bound set of instances.
- `item.viewId` names the registered View to render.
- `item.presence` is required and sets the item's presence. `"fixed"` means the item is always open while its owner is
  active; the user cannot close it, and the Add panel does not offer it. `"open"` means the item starts open when the
  owner has no saved state, and the user may close it. `"closed"` means the item stays hidden until the user or an
  action opens it from the Add panel. A saved user choice wins over `"open"` and `"closed"` on the next visit. Every
  placement here uses `"fixed"` so the whole map stays visible.
- `region` names the target region from the canonical `workbenchRegions` list.
- placements carry no size or collapse settings. Region layout policy lives in `regionSettings` on the mode
  (`defineMode({ regionSettings })`) or on the host (`createWorkbench({ regionSettings })`), and the active mode's
  settings win over the host's.

The panel menus:

- `ctx.viewMenus.registerViewMenu({ id, ownerViewId, viewId, side, regionSize })` attaches a menu to one edge of a panel
  View.
- `ownerViewId` names the panel View the menu belongs to. The menu appears wherever that View is placed.
- `viewId` names the View rendered inside the menu.
- `side` is `"left"` or `"right"`.
- `regionSize` sets the menu region's width in pixels. `defaultPx` is the starting width and `minPx` the minimum. This
  field belongs to view menus only; placements have no size field.
