# 15. Persist layouts at the right scope

Users can arrange panels differently per project or workspace. A layout scope selects which persisted arrangement is
active. Changing scope stores the old layout and restores the target layout.

Scope is host state. Extensions contribute placement rules but do not choose persistence keys or restore layouts on
their own.

## What each field means

The host wires persistence into the workbench:

- `createWorkbench({ layoutPersistence, panelsPersistence })` accepts one adapter for region layout and one for panel
  open state. The example uses in-memory maps; a real host writes to disk or a database.
- `LayoutPersistenceAdapter` has `getLayout(scope)` and `setLayout(layout, scope)`. The workbench calls them with the
  active scope key, so the adapter stores one layout per scope.
- `WorkbenchPanelsPersistenceAdapter` has `getPanelStates(scope)` and `setPanelStates(state, scope)` for panel open
  state, keyed the same way.

Scopes name one persisted arrangement:

- A `LayoutScope` is a string key such as `"project/demo/mode/tickets/resource/ticket:PS-100"`. The host chooses the
  key format; the workbench only uses it to store and look up state.
- `workbench.layout.setPersistenceScope(scope, options?)` saves the current layout under the old scope and restores
  the layout saved under the new one.
- `carryRegionState: ["sidenav"]` keeps the named regions unchanged across the switch. The example uses it so the
  project-owned Sidenav does not remount while resource scopes rotate.
- `workbench.panels.setPersistenceScope(scope)` does the same switch for panel open state.
- `workbench.layout.getPersistenceScope()` returns the active scope key. It lives outside the store, so the example
  mirrors it in local state to drive the button highlight.

The demo controls change state that the scope persists:

- `workbench.layout.setRegionSize("secondary", size)` resizes one region.
- `workbench.panels.setOpen("secondary", open)` and `workbench.layout.setRegionVisible("secondary", open)` open or
  close the Secondary Panel region.
- `useWorkbenchStore(workbench.layout.store, selector)` and `useWorkbenchStore(workbench.panels.store, selector)`
  subscribe to the live values so the panel re-renders after each switch.

The rest is the standard module setup:

- `ctx.views.registerView(...)` defines each demo View with a React `body`.
- `ctx.shellPlacements.registerPlacement(...)` places each View. `item.presence: "fixed"` keeps them open, and
  `region` picks `main`, `sidenav`, or `secondary`.
- The story seeds three scopes with different Secondary Panel sizes and open states, so switching shows a visible
  difference.
