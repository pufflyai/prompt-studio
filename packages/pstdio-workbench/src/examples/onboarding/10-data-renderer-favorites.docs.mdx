# 10. Add A Data Workspace (Tables, Boards, Saved Views)

If you need a Notion/Linear-style data view — sortable, filterable, with board
and list layouts, saved views, and favorites — register a **data renderer**
instead of a plain renderer.

<Canvas of={OnboardingStories.DataRendererAndFavorites} sourceState="shown" />

You provide:

- The **schema** — tag definitions, the fields users can group/sort/filter by,
  the display properties they can toggle on cards.
- An **`executeQuery({ settings, filters })`** that returns rows. Return all
  rows for simple cases; push the filter down to your backend when it matters.
- Row-mutation callbacks for click, drag, tag change, etc.
- An optional `savedViews: { resourceKind, scope, projectId? }` block. With
  that set, the workspace toolbar shows a save / save-as / rename / duplicate
  / delete menu wired to `workbench.savedViews` — you don't write any
  save-view UI yourself.

Like the tree renderer, `registerDataRenderer` auto-creates a widget renderer
with the same id; you place it with `layout.registerWidget` and open it the
usual way.

The story's sidebar has Favorites and Views sections. Open a saved view to
see its filter and display state applied to the workspace; tweak the filters
to see the "Unsaved" badge appear, then save. Right-click a view in the tree
to add it to Favorites.
