# 0. Create a workbench

This guide is for host application developers. It uses the Core API from `@pstdio/workbench`.

`createWorkbench()` creates the platform services. `Workbench` renders those services. An empty workbench has no
panels because the host and extensions have not contributed anything yet.

Create one workbench for the lifetime of the host view. Render it inside `WorkbenchThemeProvider`.

## What each field means

- `createWorkbench()` creates one workbench service container. Every registration in the later guides goes through
  this container.
- The example calls it once at module scope, so the same container lives as long as the host view.
- `WorkbenchThemeProvider` supplies the theme tokens the workbench components need. Render it once, above the shell.
- `Workbench` is the React component that renders the shell layout.
- The `workbench` prop connects the rendered shell to the service container. The shell shows whatever that container
  holds, which is nothing yet.

The next guide adds a placeholder without changing the shell.
