# 8. Declare the whole page composition

A page declares its Main content through `main` and additional panels through `slots`. This story renders two workbenches so both compositions remain
visible. It does not demonstrate navigation. Story 8 does that.

The first workbench shows Session details in Main, changed files in the Sidenav, and a session inspector in the
full-height Side panel. The second shows Extension Lab in Main, contributions in the Sidenav, and validation output in
the bottom Secondary panel.

## What each field means

The outer setup prepares the workbench:

- `createWorkbench({ startPage })` creates the service container and names the page to open first.
- `workbench.modes.registerMode(...)` declares each mode. `id` is the mode identity and `activate` runs when the mode
  becomes active. This example needs no activation work.
- `workbench.pageLocations.switchProject(...)` selects the active project and opens that workbench's start page.

`registerPage(...)` defines three Views for each page:

- the Main View renders the concrete page content.
- the Sidenav View renders page-specific context.
- the auxiliary View renders in the region chosen by that page. Session uses `side`; Extension Lab uses `secondary`.
- each View `id` is stable. Its matching page slot refers to it.
- `title` is the default user-facing label.
- `body.kind: "react"` allows trusted host code to return React.
- `render` receives the render input. `input.workbench` exposes the core services.

`workbench.pages.registerPage(...)` declares each page and its composition:

- `id` is the stable identity of this page registration.
- `ref` is the public page reference `{ extensionId, kind: "page", id }`. Navigation targets address the page through
  this value.
- `title` is the user-facing page name.
- `path` is the URL path segment for the page location.
- `modeId` names the mode that owns the page. Opening a page from another mode switches the mode in the same
  navigation step.
- `main: { kind: "view", view, cardinality: "one" }` renders the Main view.
- `slots` declares the fixed Sidenav panel and the additional panel in `page.auxiliary.region`. Session uses Side; Extension Lab uses Secondary. Each uses the shared `item` contract.

`PageCompositionExample` creates two workbenches with different start pages. It renders both at once so the region
layouts can be compared without changing state. `showNavigation: false` removes the replacement controls from this
story.

Do not open page-owned panels from an activation callback. The page registry is the source of truth, so the runtime can
add and remove the complete page contribution as one unit.
