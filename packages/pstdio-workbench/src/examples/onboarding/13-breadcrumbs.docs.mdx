# 11. Navigate a full location trail

Breadcrumbs describe the active location and its parents. This story starts at `workbench-core.ts` inside a pull request
review. The header shows five levels: Prompt Studio, Pull requests, #646 Additive pages, Files changed, and the current
file.

The story reached the file by navigating through each parent page. That created real history. Press Back in the header
to return to Files changed. Forward becomes available and returns to the file. Click a breadcrumb ancestor or a button
in Main to create another history entry.

For resource hierarchies, register canonical parent edges and derive the breadcrumb trail from those resources. Avoid a
separate hierarchy that can disagree with navigation.

## What each field means

The setup creates the workbench and its page mode:

- `createWorkbench({ startPage })` creates one workbench and names Prompt Studio as its first page.
- `modes.registerMode(...)` registers the Review mode used by all five pages.
- `breadcrumbPages` stores the page identity, label, path, icon, and declared parent.

`workbench.views.registerView(...)` and `workbench.pages.registerPage(...)` build each location:

- the View uses `body.kind: "react"` to render the active location and page buttons.
- `main` renders the page content; `resource` declares its routed resource constraint.
- `parentId` points to the registered parent page. The location controller follows those links to build the breadcrumb
  trail.

The final loop creates the navigation history:

- `switchProject("breadcrumb-story")` opens the root page, Prompt Studio.
- each call to `pageLocations.navigate(...)` opens the next child and pushes a history entry.
- the workbench derives breadcrumbs from the active page and its declared parents. The story never calls
  `breadcrumbs.setItems(...)`.
- Back and Forward replay those saved page locations, so the panel content and breadcrumb trail move together.
