# 13. Surface Where the User Is

Breadcrumbs answer "where am I in the workbench" and "what is above this view".
The workbench owns the trail as a controller (`workbench.breadcrumbs`), and the
default `Workbench` top header renders it for you.

<Canvas of={OnboardingStories.Breadcrumbs} sourceState="shown" />

A resource opener typically owns the trail for its resource. Each call to
`ctx.breadcrumbs.setItems(...)` replaces the entire trail, so the opener
decides exactly what shows up — there is no auto-derivation from the tree.

Give every level its own widget so clicking back up the trail lands on a real
page. This story registers three resource kinds (`docs.root`, `docs.section`,
`docs.page`), each with its own opener and renderer: the root opens a docs
home, sections open a category index, pages open the leaf widget. The
breadcrumb `onClick` for every entry except the active one re-runs
`ctx.resources.openResource(...)`, which keeps the controller as the single
source of truth for both the trail and the active widget.

A breadcrumb item is:

- `title` — visible label (string or React node).
- `icon?` — workbench icon name rendered before the title.
- `resource?` — ties the entry to a resource ref.
- `url?` / `onClick?` — optional navigation hooks the `Breadcrumb` UI wires up.

To render the trail somewhere other than the default top header (a custom
main-area header, a tab strip, an embedded view) use the dedicated view:

```tsx
import { WorkbenchBreadcrumbView } from "pstdio-workbench/react";

<WorkbenchBreadcrumbView workbench={workbench} />;
```

The view subscribes to `workbench.breadcrumbs.store` itself and returns `null`
when the trail is empty, so it can sit unconditionally in any header layout.
