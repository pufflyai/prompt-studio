# 5. Add Resources

A `ResourceRef` is a typed identity: `{ kind, uri, id?, label?, icon?, metadata? }`.
Trees, navigation, favorites, and saved views all speak in resource refs so
identity is consistent across surfaces.

<Canvas of={OnboardingStories.Resources} sourceState="shown" />

`resources.openResource(resource)` routes through registered openers. Each
opener has a `canOpen(resource)` predicate and a `priority` — the highest
matching opener wins. The opener decides which widget hosts the resource and
calls `layout.openWidget(widgetId, { resource })`.

Two behaviours fall out of this routing:

- **Identity-based dedup**: opening the same resource twice activates the
  existing placement instead of creating a duplicate (the widget's
  `singleton: true` plus the matching resource URI handles this).
- **Decoupled providers**: trees, search palettes, and external links all
  produce `ResourceRef`s and call `openResource` — they don't need to know
  which widget will render the content.

Required registrations:

- `resources.registerKind({ kind, label, icon })` — names the type.
- `resources.registerOpener({ id, canOpen, open })` — routes refs to widgets.
- Tree nodes attach a `resource` field; clicking calls `openResource` for you.
