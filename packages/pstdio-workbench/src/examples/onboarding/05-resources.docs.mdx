# 5. Make Tree Nodes Open Tabs

To make a tree node open a tab when clicked, give it a `resource` ref and tell
the workbench how to open that kind of resource.

<Canvas of={OnboardingStories.Resources} sourceState="shown" />

Three pieces:

- `resources.registerKind({ kind, label, icon })` — declares the type once.
- `resources.registerPresenter({ canOpen, open })` — maps a Resource to the
  Panel instance that presents it.
- Attach `resource: { kind, uri, label }` to each tree node.

Standard icon names for shared resource concepts:

| Concept       | Icon                      |
| ------------- | ------------------------- |
| Project       | `folder-root`             |
| Workspace     | `computer`                |
| Worktree      | `git-pull-request-draft`  |
| Ticket        | `component`               |
| Kanban renderer | `square-kanban`           |
| Settings      | `settings`                |

Now clicking a node calls `resources.openResource`. The resource service selects
a presenter, waits for it to return a Panel, and then makes that Panel the active
navigation Location. History, breadcrumbs, and resource scope follow that
successful navigation.

Calling `layout.openPanel` directly only displays a Panel. It does not create a
Location or history entry. Use that direct operation for supporting Panels whose
definitions declare `eligibleLocations`.

Build your features around resources whenever there's a "thing you can open".
History and navigation both speak resource refs, so your tree rows, command
targets, and routed widgets can share the same data shape.
