# 3. Add A Command Surface

A command is an indirection layer: `{ id, label, execute, isEnabled? }`. Menu
items, keybindings, and tree-node actions reference command ids — they don't
hold the handler directly.

<Canvas of={OnboardingStories.CommandAndMenu} sourceState="shown" />

The indirection earns its keep when more than one surface needs the same
action. Add a keybinding later without touching the menu wiring; gate
visibility centrally with `isEnabled`; let `commands.onDidExecuteError` observe
every invocation regardless of how it was triggered.

This story registers one command and surfaces it twice:

- `commands.registerCommand({ id, ..., execute })`.
- `layout.registerMenuItem(headerTrailingMenuPath("main"), { commandId })` —
  shows it in the main header.
- `layout.registerMenuItem(workbenchCommandPaletteMenuPath, { commandId })` —
  shows it in the command palette.

The shell renders both surfaces; both fire the same handler. The story opens
on the placeholder so you can see the menu action open the widget.
