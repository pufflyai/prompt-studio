# 17. Give a page its own Sidenav level

A page can own a `content` navigation tree. Opening that page starts a Sidenav level: the page's sections replace the
mode's body, so the Sidenav shows only what belongs to the page. Header and footer rows stay.

Press Recipes to enter the level. The recipe list replaces the project rows, while Pantry stays in the header. Open a
recipe: its page declares Recipes as its parent, so the level stays open. Press the fixed ← Project button at the
top of the main navigation content to return to the main level. It shows the current mode name and cannot be moved or hidden.
The breadcrumb and browser history also remain available.

## What each field means

- `defineNavigationItem({ owner: workbenchModes.project, slot: "header" })` adds a header row to the mode. Header and
  footer rows accumulate from the mode through every open level, so they stay visible in nested levels.
- `defineNavigationItem({ slot: "content", action: { kind: "page", page } })` adds the one main-level row that opens
  the level page.
- `defineNavigationTree({ owner: recipesPage.ref, slot: "content", view })` gives the page its own tree. A page owner
  starts a level; a mode owner adds sections to the main level instead.
- `resourceScope: "project"` reads the tree once for the project. Selecting a recipe keeps its rows visible.
- `parent: recipesPage.ref` on the recipe page keeps the Recipes level open for every recipe. Levels follow the page
  location's parent chain, so a level page opened from another level nests inside it.
- Rows set `resource` as their action subject and `target` as their click destination.

Users can drag rows into the header or footer. Those rows also stay visible inside levels. In the customize menu, users
can hide a level's labeled sections but not its rows. The mode return button stays first in the main navigation content, with the same spacing as other entries.

## Leaving a level

When a child page uses the same resource as its parent, its breadcrumb shows the child page title. The parent keeps the resource label, so the trail names both the resource and the current page.

A level page with no declared parent, such as Recipes, starts the breadcrumb. The host provides a mode return entry
in the navigation panel so users can leave the level.

- Every breadcrumb item that opens a level carries `startsLevel: true`. So does an item whose page belongs to a mode
  that sets `chrome.sidenav`, because that mode also hides the project rows. Hosts can read `items[0].startsLevel`
  when adding their own navigation controls.
- `workbench.pageLocations.navigateToRootLevel()` opens the last location outside every level and every such mode, or
  the start page when there is none. The workbench records that location on every navigation and saves it with the current location, so it
  survives a reload.
- In Prompt Studio, the mode return entry and the active desktop project tab call the same operation. The desktop
  breadcrumb shows only page and resource crumbs. The browser navbar also keeps the project avatar and title as a
  return control.

## Host API

`createLevelNavigation(workbench)` composes one navigation tree from the active mode and every open level. Hosts use
it to fill their navigation view:

- `getSections(slot, signal, onProgress)` returns the sections for `header`, `content`, or `footer`. Pass the tree
  query's `onProgress` callback to show ready sections while slower contributions finish. Results keep their declared order.
- `getReadKey()` changes when the owners or their resources change, so the tree starts a new read.
- `getDefaultExpandedSectionIds()` lists the sections that start expanded.

Outer body rows are returned with `pinnedOnly: true`. The tree view shows them only where users pinned them.
