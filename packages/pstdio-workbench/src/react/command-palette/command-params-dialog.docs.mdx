# Command parameters

Command parameter schemas describe values that must be collected before a command runs. The workbench renders one
shared dialog from the schema, applies defaults, validates required values, and passes normalized arguments to the
command handler.

Each example now lives on this guide page. Press **Open parameter form** to try it, then compare the schema with the
form the workbench created.

## When a command fails

When the command throws, the dialog stays open and shows the error message in an error box above the actions. The
field values stay, so the user can fix the cause and press **Run** again. Press **Open parameter form**, then **Run**, to
see the planner's "Run attempt" refusing a ticket that waits on another one.

<Canvas of={CommandParameterStories.RunFailed} sourceState="none" />

## Rules

Define parameters on the command. Do not build another form beside the command surface.

Parameters with `resolvedFrom: "resource"` are supplied by the active resource and are not shown to the user. Use host
field renderers only for structured parameter types that the shared editor cannot render.
