---
name: run-cloud-tests
description: Run repository tests in an isolated workspace on the deployed PocketCoder controller, collect logs, and check automatic shutdown. Use for cloud test runs against a branch or working tree.
---

Run agent tests primarily in cloud workspaces, including focused red/green checks and review gates. Cloud Workspaces uses the private Remote Testing companion (`pocketcoder.remote-testing`) for source upload, run collection, and cleanup. Run `pst` from the linked local project. Operator connections and Google authentication stay on the host.

Check setup with `pst pocketcoder.remote-testing status`. If unavailable, inspect the reported problem. Configure host connections through Prompt Studio connection settings. Never copy operator keys, Google credentials, runtime tokens, or environment files into extension assets or cloud source. Candidate and comparison-base Git history is included; inspect it for secrets as well as the selected tree. Host configuration and hooks are excluded. Ignored untracked files are omitted, but tracked files remain in the upload even if an ignore rule now matches them. Before uploading a working tree, inspect the full candidate file list from `git -C /absolute/repository ls-files -z --cached --others --exclude-standard`, including unchanged tracked files. For `--ref`, inspect `git -C /absolute/repository ls-tree -rz --name-only <commit>`. Check those files and their contents for environment files, credentials and other secrets; `git status --short` alone cannot find unchanged tracked secrets. Remove sensitive content from the selected snapshot before starting a run. An ancestor commit in the uploaded candidate or comparison history can still contain a credential; if inspection finds one, do not upload that history. Rotate the credential and choose a history without it.

Start a run with an explicit repository path and test command:

```sh
pst pocketcoder.remote-testing run --path /absolute/repository --command "bun install --frozen-lockfile && bun run test:unit" --timeout-minutes 30 --wait false
```

Choose a command that actually exists in that repository. The example does not select a suite for you. `--path` uploads the current working tree, including non-ignored new files. Add `--ref <commit>` for an exact committed snapshot. Branch runs use the approved test runtime; do not invent a template name for each agent. `--branch-template true` is available when an immutable snapshot template is needed.

Each run starts a fresh workspace by default. To reuse one you intentionally kept, pass `--environment <environmentId>`. `--wait false` still waits for provisioning and request submission before returning IDs; it skips waiting for the test result. Save the returned `runId` and `environmentId`, then collect the result:

```sh
pst pocketcoder.remote-testing runs show --run-id <runId>
```

Report `status`, `exitCode`, tested revision or dirty snapshot, command, and `logPath`. Read failures from the full local log; the returned tail can omit the cause. Check the workspace in Cloud Workspaces or `pst pocketcoder.remote-testing environments list`. With the default cleanup policy, after the controller finalizes a test (including a failed test), the collector stops its workspace before downloading the uploaded log and saving the local log and summary, provided it can renew that run's environment claim. With `--keep-environment true` or a claim it cannot renew, collection can save the result without stopping the workspace; a saved summary does not prove shutdown. A stop failure can therefore leave collection pending or failed without a saved summary; `runs show` cannot return that result yet. Transient stop failures retry automatically. Correct a permanent connection or permission problem, then run `runs show --run-id <sameRunId>` again to resume collection of the existing execution. Do not submit the tests again to recover collection. Verify shutdown for that saved environment ID. Before a manual stop, inspect the environment and run listings for another active run; stop an owned leftover only when no other run owns or uses it. If ownership is uncertain, leave it running and report its IDs rather than disrupting another run. Do not use `--keep-environment true` unless the task needs it.

The equipped test runtime supplies Docker and Compose through a daemon dedicated to each workspace. Uploads include a self-contained Git repository, comparison refs and history without host Git configuration, hooks or credentials. Check `docker info`, `docker compose version` and `git merge-base origin/main HEAD` before review on an older deployment; ask the operator to upgrade it if prerequisites are missing. For review, commit the candidate, fetch the intended base on the host, then run `--ref <commit>` with `--command "bun install --frozen-lockfile && bun run test:review --base origin/main --desktop-in-ci"`. The flag leaves native desktop checks to GitHub Actions; require passing evidence for that exact candidate. Install the repository-pinned Playwright browser when selected suites need it. Focused checks do not replace the review gate. The runtime is Linux amd64. Do not silently skip required suites when a prerequisite is missing.

For interrupted or unwanted runs, use `pst pocketcoder.remote-testing runs cancel --run-id <runId>`. Stop an owned leftover workspace with `pst pocketcoder.remote-testing environments stop --environment <environmentId>`. Do not stop another agent's workspace or use `--all` during concurrent work.

Source history covers the selected candidate and comparison base, with refs pointing into those histories. The default base is `origin/main` (then local `main` or `master` when available). Choose a named branch, tag, custom ref or commit SHA; resolve HEAD-relative expressions to a SHA on the host. Pass `--base <ref>` to the remote command for another comparison base, and use the same base in `test:review`. Fetch it on the host before upload. Unrelated workspace branch histories stay on the host.
